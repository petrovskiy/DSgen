# AGENTS.md

Правила для ИИ-агента, разрабатывающего продукт DSgen (сам генератор, не то, что он экспортирует пользователям).

## Текущее состояние проекта

- **Прототип** (`prototype/`) — полностью готов. Интерактивный HTML/CSS/JS визард: 4 шага (Концепция → Палитра → Шрифты → Превью), экспорт ZIP.
- **React-приложение** — разработка начинается. Стек: Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui. Приложения на диске ещё нет — первым шагом будет инициализация проекта.
- Прототип — источник правды по логике, данным и поведению. При портировании на React сверяйся с `prototype/assets/app.js` и `prototype/assets/styles.css`.

## Обязательный порядок действий

Перед ЛЮБЫМ изменением UI, стилей или компонентов:

1. Прочитай `docs/02-design/design-system.md` — токены и компоненты самого DSgen (цвета «Тихий синий», Tenor Sans + Manrope, 4px-сетка).
2. Прочитай `docs/02-design/screen-start.md`, `screen-editor.md`, `screen-export.md` — актуальные варфреймы (обновлены под 4-шаговый визард прототипа).
3. Прочитай `docs/03-prd/PRD.md` — функциональные требования и user stories.
4. Только после этого начинай писать код.

Не начинай писать код, не сверившись с документацией.

## Не путай два разных «design system»

- **`docs/02-design/design-system.md`** — как выглядит **сам DSgen** (UI приложения-генератора). На него ориентируйся при работе над React-приложением.
- **`docs/design-system-template.md`** — шаблон, из которого DSgen **генерирует** `design.md` для пользователей. Это данные для фичи «экспорт», не спецификация UI DSgen.

## Приоритет источников

1. `docs/02-design/design-system.md` — точные значения токенов (раздел 1)
2. `docs/02-design/screen-*.md` — варфреймы экранов (обновлены под прототип)
3. `prototype/assets/app.js` + `prototype/assets/styles.css` — исполняемая правда (логика, данные, стили)
4. `docs/03-prd/PRD.md` — функциональные требования и обоснование
5. `docs/04-ux/USERFLOW.md` — пользовательские сценарии (частично устарел, описывает старый трёхэкранный флоу; сверяй с прототипом)

## Запрещено

- Придумывать hex-цвета, которых нет в `docs/02-design/design-system.md`
- Вводить новые значения spacing/radius вне 4px-сетки и радиусов 8/12/16
- Копировать UI-паттерны из общих знаний, если они противоречат «холодному минимализму» DSgen
- Молча принимать решение там, где документация неполна или противоречива — сообщи об этом

## Прототип как референс

При портировании логики на React:

- **app.js** (`prototype/assets/app.js`, ~2800 строк) содержит: семантический анализатор палитр (`analyzePalette`), генератор альтернативной темы (`generateAltTheme`), рендеринг всех шагов визарда, drawer редактирования, генерацию design.md / tokens.json / components.md, экспорт ZIP через jszip.
- **styles.css** (`prototype/assets/styles.css`, ~3300 строк) содержит: токены оболочки (светлая + тёмная тема), компоненты визарда (хедер, шаги, карточки концепций/палитр/шрифтов, превью-холст, drawer, кнопки, селекты, слайдеры).
- **Данные:** `prototype/assets/data/concepts.json` (10 концепций), `palettes.json` (40+ палитр), `fonts.json` (40+ шрифтов + 32 пары). В прототипе данные дублированы inline в app.js для работы через `file://`.

## Стиль работы

- Маленькие, проверяемые изменения — не переписывай сразу много файлов
- Переиспользуй shadcn/ui компоненты прежде чем создавать новые
- После изменения токенов в `design-system.md` — сверься, что компоненты остались консистентны
- Перечитывай `docs/` заново при каждой значимой задаче

## Технические договорённости

- **Язык:** TypeScript (strict mode)
- **UI:** Tailwind CSS + shadcn/ui, иконки — lucide-react
- **Состояние:** zustand (persist в localStorage)
- **Цвет:** culori (вместо самописных утилит из прототипа)
- **Экспорт:** jszip + file-saver
- **Шрифты оболочки:** Tenor Sans (заголовки), Manrope (body) — всегда предзагружены
- **Тёмная тема:** `data-theme="dark"` на `:root`, ключ localStorage `dsgen-shell-theme`

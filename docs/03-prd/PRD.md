# PRD: DSgen — визуальный генератор дизайн-систем и токенов

**Статус:** Draft
**Версия:** 0.1
**Дата:** 2026-08-05
**Автор:** Продуктовая команда

---

## 1. Executive Summary

### Проблема
Создание дизайн-системы с нуля — долгий и трудоёмкий процесс: дизайнеру нужно подобрать палитру, шрифты, отступы, радиусы и зафиксировать всё в токенах, а разработчику — вручную перенести их в код проекта (CSS, Tailwind, Flutter, Swift). При подключении ИИ-ассистента к проекту отсутствует единый машиночитаемый файл, описывающий дизайн-систему, из-за чего агент генерирует UI «в отрыве» от бренда.

### Решение
DSgen — веб-редактор, который за несколько минут генерирует дизайн-систему и токены: цвета подбираются по цветовому кругу (не «случайно», а по правилам гармонии), стили выбираются из готовых пресетов (стеклянный, киберпанк, минимализм и др.), шрифты подключаются из библиотеки Google Fonts. Результат — скачиваемый ZIP-архив, разбитый по папкам (токены, стили, компоненты, шрифты, документация) с единой MD-спекой и файлом правил для ИИ-агента, готовый к встраиванию в любой проект.

### Бизнес-влияние
- Сокращение времени на создание дизайн-системы с недель до минут.
- Единый источник правды (JSON-токены) с автоматической генерацией под Web, Flutter и Swift.
- Встроенный файл правил для ИИ-агента — ускорение разработки UI в проектах с ассистентами.

### Метрики успеха (KPIs)
| Метрика | Цель |
|---------|------|
| Время до первого экспорта | < 3 минут |
| Доля пользователей, редактировавших токены | > 60% |
| Конверсия «открыл → скачал архив» | > 30% |
| Повторные визиты (Retention W4) | > 15% |

### Таймлайн
- MVP: ~6 недель (дизайн — недели 1–2, разработка — 3–6).
- Бета: неделя 7.

### Ресурсы
- 1 продуктовый дизайнер, 1 фронтенд-разработчик (Next.js/TS), 1 QA (частично).

## 2. Problem Definition

### 2.1 Проблемы пользователей

| Персона | Кто | Что | Когда | Почему (корень) |
|---------|-----|-----|-------|-----------------|
| Дизайнер | UI/UX-дизайнер | Нет быстрого способа собрать связную палитру и токены | Старт нового проекта | Подбор цветов вручную долгий, нет гарантии гармонии |
| Разработчик | Frontend / Mobile разработчик | Перенос токенов в код вручную | Подключение дизайн-системы в проект | Токены не конвертируются автоматически под платформу |
| Команда с ИИ-агентом | Разработчик, использующий Cursor/opencode и т.п. | Агент не знает дизайн-систему проекта | Генерация нового UI | Отсутствует машиночитаемый файл правил (AGENTS.md) |

### 2.2 Рыночная возможность
- Ниша «дизайн-токены» активно растёт (Tools of the trade: Style Dictionary, Tokens Studio, Figma Tokens).
- Ниша «генератор + экспорт под несколько платформ + файл для ИИ-агента» — практически пуста.
- Рост популярности ИИ-ассистентов в разработке создаёт спрос на «подключаемые правила дизайна».

### 2.3 Конкуренты и пробелы
| Инструмент | Сильные стороны | Пробел DSgen закрывает |
|------------|-----------------|------------------------|
| Tokens Studio / Style Dictionary | Мощные токены, компиляция | Нет визуального генератора, нет пресетов, нет MD-спеки для агента |
| Coolors / ColorMind | Генерация палитр | Только цвета, нет полной дизайн-системы и экспорта |
| Tailwind theme builder | Пресеты, палитры | Только Web/Tailwind, нет Flutter/Swift и токенов-источника |
| Figma + плагины | Полный дизайн | Требует Figma, нет авто-экспорта в код и файла для агента |

### 2.4 Бизнес-кейс и риски
- **Стратегическая ценность:** экосистема «генерируй → скачивай → подключай агенту» создаёт конкурентное преимущество.
- **Риск «не делать»:** дизайн-системы продолжают собираться вручную, ИИ-агенты генерируют UI без бренда.

## 3. Solution Overview

### 3.1 Высокоуровневое описание
Веб-приложение с визуальным редактором: пользователь стартует с пресета стиля или кнопки «Сгенерировать», редактирует цвета/типографику/отступы/радиусы/тени, подключает Google Fonts и скачивает ZIP-архив с дизайн-системой.

### 3.2 Ключевые возможности
1. **Генератор палитры по цветовому кругу** — гармонии: аналоговая, комплементарная, триадная, тетрадная, монохромная + проверка контраста WCAG (AA/AAA).
2. **Пресеты стилей** — стеклянный (glassmorphism), киберпанк, минимализм, неоморфизм, брутализм, плоский, тёмный/светлый.
3. **Визуальный редактор токенов** — цвета, типографика, отступы (spacing), радиусы, тени, z-index, брейкпоинты.
4. **Интеграция Google Fonts** — поиск, предпросмотр, выбор семейств и начертаний.
5. **Экспорт универсального архива** — Web (CSS + Tailwind), Flutter (Dart), Swift (SwiftUI) + общие JSON-токены, MD-спека и файл правил для ИИ-агента.

### 3.3 User Journey
```
Старт (пресет / «Сгенерировать») → Редактор токенов → Предпросмотр → Скачать ZIP → Распаковать в проект → Подключить агента (AGENTS.md)
```

### 3.4 Дифференциация
- Единый источник правды (JSON-токены) → экспорт под несколько платформ.
- Встроенный файл правил для ИИ-агента (AGENTS.md / MD-спека).
- Палитра не случайная, а по правилам цветовой гармонии с проверкой контраста.

- **Learning goals:** какие пресеты и гармонии популярны, востребована ли точечная перегенерация элементов, какой формат экспорта нужнее.

**US-001 — Генерация палитры**
```
As a дизайнер
I want to сгенерировать палитру по цветовому кругу
So that цвета гармонировали без ручного подбора

Acceptance Criteria:
- [ ] Кнопка «Сгенерировать» создаёт палитру из базового цвета
- [ ] Доступны 5 гармоний: аналоговая, комплемент, триада, тетрада, монохром
- [ ] Отображается контраст каждой пары (WCAG AA/AAA)
- [ ] Палитра перегенерируется и меняется базовый цвет
```

**US-002 — Пресеты стилей**
```
As a дизайнер
I want to выбрать готовый стиль (стеклянный, киберпанк и т.д.)
So that получить целостную систему без настройки с нуля

Acceptance Criteria:
- [ ] Панель пресетов с миниатюрами
- [ ] Выбор пресета заполняет все токены
- [ ] Пресет можно открыть и отредактировать

As a разработчик
I want to редактировать токены визуально

Acceptance Criteria:
- [ ] Группы: colors, typography, spacing, radius, shadow, z-index, breakpoints

- [ ] Сброс к значениям пресета

I want to подключать шрифты из Google Fonts
So that использовать проверенные семейства

```
As a пользователь
I want to сохранять проект локально
So that продолжить редактирование позже

Acceptance Criteria:
- [ ] Состояние проекта в localStorage
- [ ] Восстановление при повторном открытии

## 5. Design & User Experience

### 5.1 Дизайн-принципы
1. Минимум шагов до результата — старт с пресета или одной кнопки.
2. Живой предпросмотр — изменения токенов сразу видны.
3. Понятная иерархия: конфигурация слева, предпросмотр справа.
4. Результат ценен и для человека, и для машины (MD + токены).

### 5.2 Ключевые экраны

**Экран 1 — Старт**
- Панель пресетов (карточки с миниатюрами) + кнопка «Сгенерировать случайно».
- Пресеты: стеклянный, киберпанк, минимализм, неоморфизм, брутализм, плоский, светлый/тёмный.

**Экран 2 — Редактор**
- Слева: аккордеон групп токенов (Цвета / Типографика / Отступы / Радиусы / Тени / Z-index / Брейкпоинты).
- Справа: живые превью (палитра, типографика, кнопка, карточка, форма).
- Верхняя панель: пресеты, Google Fonts, «Скачать архив».

**Экран 3 — Экспорт**
- Модальное окно: выбор платформ (Web/Flutter/Swift), подтверждение структуры архива, скачивание.

### 5.3 Информационная архитектура
- Одностраничный флоу: Старт → Редактор → Экспорт (модальное окно).
- Никакой многоуровневой навигации в MVP.

## 6. Technical Specifications

### 6.1 Архитектура
- **Frontend:** Next.js (App Router) + React + TypeScript (strict).
- **UI:** Tailwind CSS + shadcn/ui (компоненты в `@/components/ui/`), иконки — lucide-react.
- **Состояние:** zustand (один стор с токенами проекта, persist в localStorage).
- **Цвет:** culori (цветовые пространства, генерация гармоний, контраст WCAG).
- **Экспорт:** jszip (генерация ZIP на клиенте) + file-saver.

### 6.2 Модель данных (токены)
```
DesignSystem {
  colors: { base, harmonies, palette[] },   // + semantic: primary, accent, background, text
  typography: { families[], weights, scale }, // размеры, line-height, letter-spacing
  spacing: { scale }, radius: { scale },
  shadows: { levels }, zIndex: { scale },
  breakpoints: { sm, md, lg, xl },
  theme: { mode: light|dark, stylePreset }
}
```
Единый JSON — источник правды, из него генерируются все форматы.

### 6.3 Генерация палитры
- Базовый цвет → преобразование в HSL/OKLCH.
- Гармонии: аналог (соседние оттенки), комплемент (+180°), триада (+120°), тетрада (+90°), монохром (варьирование светлоты/насыщенности).
- Проверка контраста каждой пары по WCAG (относительная светимость), подсказки для достижения AA/AAA.
- «Случайно, но красиво»: случайный выбор базового оттенка + фиксированные правила гармонии и допустимые диапазоны светлоты.

### 6.4 Генерация экспорта
| Формат | Выходные файлы |
|--------|----------------|
| Общий | `tokens/*.json`, `docs/design-system.md`, `docs/AGENTS.md` |
| Web | `styles/globals.css` (CSS-переменные), `styles/tailwind.config.ts` |
| Flutter | `flutter/tokens.dart`, `flutter/theme.dart` (ThemeData, AppColors, AppTextTheme, AppSpacing) |
| Swift | `swift/DesignSystem.swift` (Color, Font, CGFloat, семантика) |
| Шрифты | `fonts/README.md` + ссылка подключения через Google CDN (скачивание woff2 — опционально) |
| Компоненты (P1) | `components/` — button, card, input (код + MDX-док) |

### 6.5 AGENTS.md (файл правил для ИИ-агента)
- Ссылка на `docs/design-system.md` и `tokens/*.json`.
- Правила использования токенов (запрет произвольных HEX, обязательные токены).
- Примеры корректного UI-кода под целевую платформу.

### 6.6 Безопасность
- Всё исполняется на клиенте; бэкенда нет → нет хранения персональных данных и ключей.
- Google Fonts подключается через официальный API (read-only).

## 11. Appendix

### 11.1 Гармонии цветового круга
- **Аналоговая:** соседние оттенки (±30°).
- **Комплементарная:** базовый + 180°.
- **Триадная:** 3 цвета через 120°.
- **Тетрадная:** 4 цвета через 90°.
- **Монохромная:** вариации светлоты/насыщенности одного оттенка.

# ДИЗАЙН-СИСТЕМА

> Этот документ — источник истины по визуальному оформлению проекта.
> AI-агенты ОБЯЗАНЫ следовать этим правилам при создании или изменении UI.
> Не изобретайте визуальные стили, противоречащие этому документу.

---

## 🧭 ИНСТРУКЦИЯ ДЛЯ АГЕНТА-ЗАПОЛНИТЕЛЯ

> Этот блок предназначен для агента, который заполняет шаблон конкретными
> данными проекта. При финальной генерации документа для пользователя
> этот блок нужно удалить.

Правила заполнения:

1. **Не оставляй плейсхолдеры пустыми.** Если данных для поля нет — не изобретай значение произвольно, а выведи его из уже заданных решений (direction, keywords, ближайший аналог из раздела 8 «Дизайн-паттерны» или другого заполненного поля).
2. **Направление (Design direction) должно физически подтверждаться токенами.** Если direction содержит слова вроде «неоновый», «футуристический» — в разделах Shadows и Color обязаны появиться соответствующие glow/яркие акценты. Если direction — «тёплый минимализм» — shadows должны быть мягкими/почти отсутствующими, а не neon glow. Расхождение между разделом 1 и разделами 3/9 — ошибка заполнения, а не вариативность.
3. **Каждый цвет из Palette должен использоваться хотя бы в одном компоненте.** Неиспользуемые цвета — сигнал, что либо палитра раздута, либо токены компонентов заполнены не до конца.
4. **Primary и Primary Hover/Active не могут совпадать.** То же для любых пар default/hover, default/active — иначе интерактивность визуально не считывается.
5. **Text Primary не должен по умолчанию совпадать с Primary (акцентным) цветом**, если явно не обосновано в разделе 28 «Текущие решения». Акцентный и основной текстовый — разные роли, их слияние ломает переиспользуемость токена при ребрендинге.
6. **Заполняй все состояния, а не только Default.** Для Button/Input — обязательны hover, focus, disabled как минимум; error и loading — где применимо.
7. **Если чего-то не хватает** — следуй протоколу из раздела 24: посмотри существующие компоненты → существующие токены → ближайший паттерн → консистентность важнее новизны.
8. После заполнения прогони чек-лист валидации в разделе 26.1 — это не опционально.

# 5. СИСТЕМА ОТСТУПОВ

Используй последовательную шкалу отступов.

```text
Базовая единица: [4px / 8px]

3xs: [значение]   ← обязательно для gap между иконкой и текстом, паддингов бейджей
2xs: [значение]
xs:  [значение]
sm:  [значение]
md:  [значение]
lg:  [значение]
xl:  [значение]
2xl: [значение]
3xl: [значение]
4xl: [значение]
```

> ⚠️ Если базовая единица большая (16px, как в примере ниже), обязательно добавь под-единицы 4px/8px отдельным блоком — иначе агенту при генерации мелких элементов (иконка+текст, паддинг бейджа) не из чего будет выбирать, и он либо возьмёт слишком крупный шаг, либо придумает произвольное значение.

## Правила

* Отдавай предпочтение токенам отступов, а не произвольным значениям.
* Поддерживай последовательный вертикальный ритм.
* Связанные элементы — меньший отступ.
* Разделы — больший отступ.

# 24. ПРАВИЛА ДЛЯ AI-АГЕНТА

## Обязательно

AI-агенты ОБЯЗАНЫ:

* Следовать этой дизайн-системе.
* Переиспользовать существующие компоненты.
* Переиспользовать существующие токены.
* Сохранять визуальную консистентность.
* Проверять адаптивное поведение.
* Учитывать все релевантные состояния UI.
* Предпочитать существующие паттерны созданию новых.
* Помнить о доступности.

## Запрещено

AI-агентам ЗАПРЕЩЕНО:

* Вводить случайные цвета.
* Вводить случайные семейства шрифтов.
* Произвольно менять радиус скругления.
* Создавать ненужные компоненты.
* Смешивать разные библиотеки иконок.
* Добавлять градиенты без разрешения.
* Добавлять избыточные тени.
* Добавлять декоративную анимацию без цели.
* Пересобирать существующие компоненты без необходимости.
* Создавать визуально отличающуюся страницу без задокументированной причины.

## Если решение не определено

Если визуальное решение не указано в документе:

1. Изучи существующие компоненты.
2. Изучи существующие токены.
3. Следуй ближайшему существующему паттерну.
4. Предпочитай консистентность новизне.
5. Вводи новый паттерн только при необходимости.

Не изобретай новый визуальный язык.

# 25. ПРАВИЛО ПЕРЕИСПОЛЬЗОВАНИЯ КОМПОНЕНТОВ

Перед созданием нового компонента проверь, можно ли существующий:

* переиспользовать;
* скомпоновать;
* расширить;
* сконфигурировать.

Создавай новый компонент только тогда, когда существующая архитектура объективно не может поддержать нужное поведение.

Порядок действий: **Переиспользовать → Скомпоновать → Расширить → Создать**

# 26. ЧЕК-ЛИСТ ВИЗУАЛЬНОГО QA

## 26.1 Валидация консистентности заполнения (для заполняющего агента)

Перед сдачей заполненного документа проверь:

* [ ] Design direction (раздел 1) соответствует цветам и теням (разделы 3, 9) — например «неоновый» не сочетается с полным отсутствием glow-теней и приглушённой палитрой.
* [ ] Primary ≠ Primary Hover ≠ Primary Active.
* [ ] Text Primary не совпадает с Primary, если это не обосновано в разделе 28.
* [ ] Каждый цвет из Palette (раздел 3) используется хотя бы в одном компоненте (раздел 10) или явно помечен как «резервный».
* [ ] Есть под-единицы отступов для мелких элементов (4–8px), если базовая единица ≥ 16px.
* [ ] Для Button и Input заполнены минимум hover/focus/disabled состояния.
* [ ] Breakpoints (раздел 6) и адаптивное поведение (раздел 14) заполнены, а не оставлены пустыми при наличии пункта в чек-листе ниже.

## 26.2 Финальный чек-лист перед сдачей UI

### Разметка

* [ ] Выравнивание последовательно.
* [ ] Отступы соответствуют системе отступов.
* [ ] Ширина контейнеров последовательна.
* [ ] Нет случайного overflow.

### Типографика

* [ ] Верный шрифт.
* [ ] Верная иерархия.
* [ ] Верные начертания.
* [ ] Читаемая длина строки.

### Цвета

* [ ] Используются только утверждённые токены.
* [ ] Контраст достаточен.
* [ ] Семантические цвета применены последовательно.

### Компоненты

* [ ] Существующие компоненты переиспользованы там, где возможно.
* [ ] Радиус последователен.
* [ ] Границы последовательны.
* [ ] Тени последовательны.

### Взаимодействие

* [ ] Hover.
* [ ] Focus.
* [ ] Active.

* [ ] Loading — где применимо.

### Адаптивность

* [ ] Mobile.
* [ ] Tablet.
* [ ] Desktop.

### Доступность

* [ ] Навигация с клавиатуры.
* [ ] Заметный фокус.
* [ ] Доступные подписи.
